# LetsClip, On Every FFmpeg Update

LetsClip ships its own FFmpeg since v2.0.10: `LetsClip.Desktop/FFmpeg/Build-FFmpeg.ps1` builds it from the pinned source in MSYS2 with only what the app runs, `scale_d3d11.patch` applied, and zips it; the zip is the asset of a GitHub pre-release on this repository (`ffmpeg-9.0.2-letsclip-1`), which `Get-FFmpeg.ps1` downloads and checks by SHA-256. Run everything below whenever that build changes, before anything ships, and write the new result into the file named beside it. Use `-frames:v` runs so no AMF process is ever killed, and wait 10 s after any kill. Part of `CLAUDE.md`, its rules bind the same way.

## Making A New Build

1. In `Build-FFmpeg.ps1` set the new source tarball and its SHA-256 from ffmpeg.org, and the MSYS2 installer's if it moves; bump the name's last number (`ffmpeg-9.0.2-letsclip-2`) for a rebuild of the same version.
2. Run it from PowerShell (`powershell -ExecutionPolicy Bypass -File LetsClip.Desktop/FFmpeg/Build-FFmpeg.ps1`); it prints each file's DLL imports, which must name only Windows' own DLLs and FFmpeg's. What its lines are for:
   - `--ld=g++` and `-static-libstdc++`: libvpl is C++, so a plain `gcc` link misses its symbols.
   - `pacman -Rdd mingw-w64-x86_64-ffmpeg mingw-w64-x86_64-ffms2`: x264's package pulls in MSYS2's own FFmpeg, whose static `libavutil.a` then links into the shared DLLs.
   - Decoders keep `wrapped_avframe` (every `lavfi` input, the encoder tests) and `pcm_f64le`; the muxer and demuxer are named `pcm_f32le`, not `f32le`.
   - Filters, parsers and bitstream filters are all built, so a filter the app starts to use needs no rebuild.
3. If the patch no longer applies, see whether stock `scale_d3d11` works now (the first row below) and drop the patch if it does.
4. Run every command form LetsClip uses against the new folder (a throwaway Git Bash script in the scratchpad, each run under `timeout 120`): the encoder test for `h264_amf`, `hevc_amf` and `libx264`; a monitor capture on the CPU route and on the GPU route; the audio capture with three tracks from a four channel `f32le` pipe; the save's `concat:` join to MP4 with track names and dispositions; the probe with packets; a thumbnail, the timeline strip and the waveform; the lossless cut; a copy export of one track; exports with `hevc_amf`, `h264_amf` and both x264 passes; the microphone chain. All 18 passed on 9.0.2 on 14 November 2026.
5. Create the pre-release with the zip as its only asset (`gh release create <name> <zip> --prerelease --title <name>`), check that `releases/latest` still points at the app's newest release, put the new URL and SHA-256 in `Get-FFmpeg.ps1`, run it into a scratch copy and compare the files with the build's, then update `LetsClip.Desktop/FFmpeg/README.md` and `THIRD-PARTY-NOTICES.txt`. Never delete an FFmpeg pre-release a pinned commit still names.

## Checks

| Check | Command Or Method | Today, LetsClip's FFmpeg 9.0.2 | If It Changes |
|---|---|---|---|
| The GPU scaler `scale_d3d11` | `ffmpeg -init_hw_device d3d11va=cap:0 -filter_hw_device cap -f lavfi -i ddagrab=output_idx=0:framerate=30:draw_mouse=0 -vf scale_d3d11=width=1280:height=720:format=nv12 -c:v h264_amf -frames:v 30 -f null -`, then the same into `hwdownload,format=nv12` with `-c:v rawvideo`, then `scale_d3d11=format=nv12` alone | Stock 9.0.2 fails all three with `Could not create the texture (80070057)` on the RX 9070 XT and on Iris Xe: its pool is one NV12 texture array of 10 (`initial_pool_size = 10` in `vf_scale_d3d11.c`), which both drivers create only for the decoder. The patch makes single textures (pool size 0) and sets BT.709 limited range on the video processor's streams and the output frames; with it the filter runs on the RX 9070 XT and its bars come out 65 dB from the CPU's BT.709 conversion (14 November 2026). Never run on Intel or NVIDIA with the patch | If stock runs, drop the patch and measure colour and range again; the downscale stays on Lanczos (`Docs/Capture.md`) |
| `gfxcapture`'s bicubic | Capture one moving window twice at once, `scale_mode=bilinear` and `scale_mode=bicubic`, and compare with `psnr` | Byte for byte the same in every `resize_mode` | A working bicubic gives the Lanczos quality at the GPU scale's cost (`Docs/Measurements.md`, Overwatch Field Test) |
| A still window | Record a window that never redraws, press save after 10 s and after 40 s | AMF and x264 hold the one frame, so the save joins the open segment after 1.5 s (`flush_packets=1`) | Simplify the still window save only if segments close by themselves |
| `-itsoffset` on the raw audio pipe | A flashing window with a 20 ms beep, read the beep against the flash in a saved clip | Ignored on `f32le`, so the audio process uses `-output_ts_offset`; the beep lands 11 to 54 ms after the flash | Keep `-output_ts_offset` unless the measured offset moves |
| The lossless cut | Cut a clip whose frames carry their own number, count the frames and hash the packets | `-ss` before `-i` with `-c copy` starts at the keyframe before and hides the lead in behind the edit list, frame exact without B frames | Any other count means `ClipLibrary.CopyRangeAsync` needs a look |
| Forced keyframes on Quick Sync | A game window session on Intel, segments must close each second | Needs `-forced_idr 1` | Drop the flag only if segments still close |
| The first Quick Sync use of a fresh copy | Time the encoder test right after the update on an Intel PC | 6 to 9 s once, then under 1 s, which the warm up at launch hides | Nothing to do if it got fast |
| The build's size and files | `Get-FFmpeg.ps1`'s SHA-256, the files `FFmpeg.HoldFiles` keeps open, `LetsClip.Desktop/FFmpeg/README.md` | 28 MB, `avcodec` 14.4 MB (BtbN's GPL build was 181 MB, `avcodec` 114 MB); the release exe 105 MB, unpacked about 233 MB | Update the hash, the README and the sizes in `Docs/Measurements.md` |
| Capture cost | The baseline in `Docs/Verify.md`: 1080p60 Normal on the monitor and on the test window, 30 s each | Monitor 59% of a core, window 32%, 1800 of 1800 frames (10 November 2026, 7800X3D, AMF, CPU route); the monitor at its own 2560 x 1440 on the GPU route 15.6% (14 November 2026) | A change of more than a few points wants a reason before it ships |
| RNNoise `arnndn` | Run `highpass=f=100,arnndn=m=<model>` 200 times on a raw `-f f32le` file of speech and noise, counting non zero exits | Segfaults in 2 to 10% of runs, never under a debugger, never on `lavfi` input (13 November 2026, stock build); left out of the voice chain | Once it runs clean, the `sh` model and the gate at 0.003 take 8.5 dB more noise from gaps (`Docs/Capture.md`) |

# LetsClip, On Every FFmpeg Update

Run every check below whenever the pinned FFmpeg in `LetsClip.Desktop/FFmpeg/Get-FFmpeg.ps1` changes, before anything ships, and write the new result into the file named beside it. Use `-frames:v` runs so no AMF process is ever killed, and wait 10 s after any kill. Part of `CLAUDE.md`, its rules bind the same way.

| Check | Command Or Method | Today, FFmpeg 9.0.2 | If It Changes |
|---|---|---|---|
| The GPU scaler `scale_d3d11` | `ffmpeg -init_hw_device d3d11va=cap:0 -filter_hw_device cap -f lavfi -i ddagrab=output_idx=0:framerate=30:draw_mouse=0 -vf scale_d3d11=width=1280:height=720:format=nv12 -c:v h264_amf -frames:v 30 -f null -`, then the same into `hwdownload,format=nv12` with `-c:v rawvideo`, then `scale_d3d11=format=nv12` alone | All three fail with `Could not create the texture (80070057)` on the RX 9070 XT and on Iris Xe. The cause is the filter's pool: one NV12 texture array of 10 (`initial_pool_size = 10` in `vf_scale_d3d11.c`), which both drivers create only for the decoder; a single NV12 texture with the filter's own flags is created fine on both (measured 10 November 2026) | Once it runs: measure colour and range on bars and the downscale against Lanczos, then it can replace `hwdownload`, `format` and `scale` for every vendor (`Docs/Capture.md`) |
| `gfxcapture`'s bicubic | Capture one moving window twice at once, `scale_mode=bilinear` and `scale_mode=bicubic`, and compare with `psnr` | Byte for byte the same in every `resize_mode` | A working bicubic gives the Lanczos quality at the GPU scale's cost (`Docs/Measurements.md`, Overwatch Field Test) |
| A still window | Record a window that never redraws, press save after 10 s and after 40 s | AMF and x264 hold the one frame, so the save joins the open segment after 1.5 s (`flush_packets=1`) | Simplify the still window save only if segments close by themselves |
| `-itsoffset` on the raw audio pipe | A flashing window with a 20 ms beep, read the beep against the flash in a saved clip | Ignored on `f32le`, so the audio process uses `-output_ts_offset`; the beep lands 11 to 54 ms after the flash | Keep `-output_ts_offset` unless the measured offset moves |
| The lossless cut | Cut a clip whose frames carry their own number, count the frames and hash the packets | `-ss` before `-i` with `-c copy` starts at the keyframe before and hides the lead in behind the edit list, frame exact without B frames | Any other count means `ClipLibrary.CopyRangeAsync` needs a look |
| Forced keyframes on Quick Sync | A game window session on Intel, segments must close each second | Needs `-forced_idr 1` | Drop the flag only if segments still close |
| The first Quick Sync use of a fresh copy | Time the encoder test right after the update on an Intel PC | 6 to 9 s once, then under 1 s, which the warm up at launch hides | Nothing to do if it got fast |
| The build's size and files | `Get-FFmpeg.ps1`'s SHA-256, the files `FFmpeg.HoldFiles` keeps open, `LetsClip.Desktop/FFmpeg/README.md` | 181 MB, `avcodec` 114 MB | Update the hash, the README and the sizes in `Docs/Measurements.md` |
| Capture cost | The baseline in `Docs/Verify.md`: 1080p60 Normal on the monitor and on the test window, 30 s each | Monitor 59% of a core, window 32%, 1800 of 1800 frames (10 November 2026, 7800X3D, AMF) | A change of more than a few points wants a reason before it ships |
| RNNoise `arnndn` | Run `highpass=f=100,arnndn=m=<model>` 200 times on a raw `-f f32le` file of speech and noise, counting non zero exits | Segfaults in 2 to 10% of runs, never under a debugger, never on `lavfi` input (13 November 2026); left out of the voice chain | Once it runs clean, the `sh` model and the gate at 0.003 take 8.5 dB more noise from gaps (`Docs/Capture.md`) |
| `vpp_amf` and AMF on BGRA D3D11 frames | `gfxcapture` into `vpp_amf=w=1920:h=1080:format=nv12`, with and without `hwmap=derive_device=amf`, and straight into `h264_amf` | `AMFConverter-Init() failed with error 10`, and `SubmitInput() failed with error 18` | Either working is a GPU path for AMF; measure colours and sharpness against Lanczos first |
| The encoder's device on a window | `gfxcapture` with AMF at `-loglevel verbose` | With `d3d11va=spare` beside `capture`, no `Using device capture ... with h264_amf` line: AMF makes its own device, sharing crashed AMD's driver (`Docs/Recovery.md`) | Keep the spare device unless FFmpeg stops handing encoders the filter device |
